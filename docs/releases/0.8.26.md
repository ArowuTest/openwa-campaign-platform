## Secure deterministic exports

- Export requests freeze purpose, criteria, template version, report as-of time and source evidence before rendering.
- Campaign reports freeze the approved report payload; audit exports freeze the audit-chain head and iterate bounded pages rather than silently stopping at 10,000 events.
- Approved exports are claimed with durable leases and become ready only after the object exists with checksum, content type and byte-size evidence.
- Retrieval uses expiring, actor-bound, single-use download grants.
- Object existence and integrity are checked before a grant is consumed.
- Revocation invalidates unused grants and every denied, failed, interrupted and completed download is audited.
- PDF output supports multiple pages; CSV/XLSX output is deterministic and neutralises dangerous spreadsheet formula prefixes.

## Privacy and data-subject governance

- Added governed cases for access, portability, rectification, objection, restriction and erasure/anonymisation.
- Cases include subject HMAC lookup, masked identity, deadline, assignment, owner, maker-checker submission/decision, separate execution authority, optimistic version and immutable events.
- Privacy legal holds follow draft, submission, independent approval/rejection, active and released states with immutable lifecycle evidence; draft or rejected holds never block processing.
- Approved objection creates an immediately effective global suppression.
- Rectification preserves pre-change profile history and permits only an allowlisted field set.
- Erasure is blocked by applicable legal holds, removes unnecessary attributes, withdraws consent, anonymises the profile and preserves minimised suppression evidence.
- Access and portability packages contain profile, source, attribute, consent, suppression and campaign history.
- Result packages are encrypted with AES-256-GCM under a dedicated privacy-evidence keyring and are never returned by ordinary case APIs.
- Controlled export decrypts only during approved rendering and verifies the plaintext SHA-256.

## Reporting privacy

- Added platform and organisation-scoped reporting-privacy policies with maker-checker approval, effective dating and supersession evidence.
- Campaign and organisation demographic/geographic breakdowns are suppressed server-side below the effective threshold.
- Reports retain the exact privacy-policy ID and version used.
- Future-dated replacement policies do not retire the currently effective policy before the boundary.

## Audience import governance

- Added bounded XLSX processing through the same protected staging pipeline as CSV.
- XLSX intake requires an unambiguous visible worksheet or an explicit selection and rejects formulas, macros, external links, embedded content, hidden-only workbooks and suspicious archive expansion.
- Added governed reusable column mappings, deterministic CSV/XLSX templates and row-level issue CSV exports with masked identifiers.
- Merge transactions capture pre-import contact state.
- Safe rollback restores prior state, removes only exclusively inserted contacts and revokes only import-derived consent; it fails closed after snapshot/campaign consumption or later profile changes.
- Source files receive governed expiry and lease-fenced, retryable deletion with append-only success/failure evidence.

## Contact lifecycle and audit

- Added governed contact lifecycle status and versioning for active, inactive, suppressed, invalid, recycled, deceased, anonymised and deleted states.
- Operational status changes are MFA-protected, reasoned and optimistic; anonymised/deleted profiles cannot be reactivated outside privacy governance.
- Added immutable contact lifecycle and profile-history evidence.
- Audit search now supports bounded cursor filters for actor, action, object, organisation, request/correlation IDs, source IP, time range, outcome and sensitivity.

## Portable object storage

- Added a common environment-selected filesystem or S3/MinIO object-store implementation.
- The S3 adapter uses AWS Signature Version 4, bounded streamed writes, independent SHA-256 metadata, exact-replay validation and verified downloads.
- Temporary local files are used only to satisfy the existing seekable-reader contract and are cleaned after use.
