## Lifecycle and evidence traps that affect the composed journey

1. **Order differs from visual wizard ordering.** The fixed model is DRAFT → CONSENT_REVIEW_PENDING → CONSENT_APPROVED → AUDIENCE_BUILDING → AUDIENCE_VALIDATED → MESSAGE_REVIEW_PENDING → MESSAGE_APPROVED → COMMERCIAL_APPROVED → FINAL_APPROVAL_PENDING → SCHEDULED. Actual mutation actions, permissions and exact expectedVersion govern progress. Content-version approval and campaign APPROVE_MESSAGE are distinct; finance record approval and campaign APPROVE_COMMERCIAL are distinct. The UI must not manufacture approvals from local step completion.

2. **Post-approval content editing is not automatically available.** createMessageVersion accepts only AUDIENCE_VALIDATED or MESSAGE_REVIEW_PENDING. material-amendment accepts AUDIENCE_VALIDATED through SCHEDULED and requires an already approved replacement message before ChangeMessage, then regresses campaign to MESSAGE_REVIEW_PENDING. A normal “edit approved content → author new version → approve → amend” path cannot simply POST a version from MESSAGE_APPROVED/later. This is a concrete lifecycle/contract reconciliation need, not proof that all content edits are impossible or permission to perform artificial no-change amendments.

3. **Approved-audience rebuild has a similar stage boundary.** Materialisation requires AUDIENCE_BUILDING; material amendment binds an existing same-campaign snapshot. The fixed action map contains no later return to AUDIENCE_BUILDING. Preserve old snapshots and explicit reapproval; do not silently replace equal-count evidence or reuse another campaign's snapshot.

4. **Final readiness is not dispatch readiness.** Accepted Unit 3 checks exact persisted evidence and re-reads campaign version, but positive state is READY_FOR_FINAL_REVIEW with current gross/advisory capacity and disclosed unassessed reservation-calendar feasibility. Final approval and execution still reload authority. Final pilot requires one exact plan route, one HELD reservation for the saved window, no reallocation, and an ACCEPTED test matching current message/hash/provider/engine/gateway/pool/adapter/frozen versions. Sender count alone is insufficient.

5. **Read routes can have different side effects.** campaignworkspace.Get calls Ensure; GET execution-plan records admission. Neither can serve as an innocent pre-final preview. Forecast is read-only but rejects earlier preparation stages. Unit 3 is the deliberately separate read-only boundary.

6. **Reuse/reopen needs explicit authority.** Clone creates fresh DRAFT identity, without valid carried snapshot/message/commercial/final approval. Archive restore is archive visibility. Organisation/review/purpose replacement, arbitrary incomplete wizard storage and creating extra entitlement are separate unresolved contracts, not hidden local state.

## Priority interpretation for future planning

The strongest next product outcome is one navigable operator preparation/review/schedule flow using existing authority, not another disconnected dashboard or raw-ID form. Its critical gaps are authoritative intake/route selectors, campaign-to-audience handoff, content/media composer and immutable-version lifecycle, controlled-test UX, exact hold evidence, reviewer detail, and timezone/typed final scheduling. This inventory does not allocate new implementation units or prescribe a design.

The source gaps that need explicit reconciliation alongside that flow are: minimum vetted-order linkage; post-approval content/audience rebuild; media inventory/safe delivery/rights; restricted-window and competing-reservation feasibility; efficient finance detail and attributable stage decisions; typed API parity. Original configurable approval policy/claim/reassign/defer, richer media library, STOP instruction policy, signed tracked links and representative samples must remain visible as missing/partial or deliberately scoped decisions. They must not be silently credited as present, nor automatically broaden the approved Day-1 operating scope.

Future composed acceptance still needs a lawful governed fixture and independent approver, actual browser create/save/reopen, source retirement/expiry, version/route drift, conflict/uncertain write, permission/session loss and stale-response cases; keyboard/focus/responsive/masking checks; exact evidence and measured outage/blocker cases. Provider text/media/send/receipt/inbound/reconnect/UNKNOWN UAT, load/capacity proof and complete accessibility remain separate evidence. The original read-only inventory ran no tests/builds, contacted no production/provider and changed no source. Root later reconciled this acceptance note and versioned the inventory; it does not certify complete UX.
