# 0.8.10 — Governed frequency-cap enforcement

This remediation release adds effective-dated organisation frequency-cap policy and enforces it consistently during cohort compilation, recipient release and final dispatch.

## Controls

- Caps are configured by purpose and channel within maker-checker organisation policy versions.
- Each cap defines a maximum message count and rolling window in hours.
- Duplicate scope definitions, invalid windows and invalid limits are rejected.
- Active campaign-recipient obligations count toward the cap; cancelled and pre-send suppressed obligations do not.
- Exceeded caps produce the explicit exclusion reason `FREQUENCY_CAPPED`.
- Campaign snapshots and dispatch no longer rely on the operator to remember frequency policy manually.

## Database

Migration `0042_organisation_frequency_cap_policy.sql` adds JSON policy storage and a contact/time index for recent-recipient checks.

## Validation boundary

The SQL paths are compiled and covered by unit/schema tests. Live PostgreSQL query-plan and scale validation remains a release gate.
