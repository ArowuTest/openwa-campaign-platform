# Designer HTML review checklist

The implementation team must review every designer delivery for:

- screen coverage against the UI/UX specification;
- semantic HTML and keyboard operation;
- loading, empty, validation, warning, permission and failure states;
- consistent navigation and design tokens;
- MSISDN masking and restricted-data states;
- campaign status terminology that distinguishes submitted, sent, delivered and read;
- responsive behaviour at 1440, 1280 and 768 pixels;
- third-party asset licences;
- duplicated or brittle CSS and JavaScript;
- missing cohort-builder AND/OR groups;
- missing long-running job progress and retry behaviour;
- missing emergency pause, session disconnect and unknown delivery outcomes.

The designer output may be expanded or replaced where it does not meet the SRS.
