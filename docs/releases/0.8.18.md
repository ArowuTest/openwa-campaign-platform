# 0.8.18 — Multi-pool routing and governed sender pacing

This operational-core release closes the transport-model gaps identified while reconciling the backend with the complete OpenWA solution discussion.

## Governed sender pacing

The backend now models versioned, effective-dated pacing policies at platform, provider, engine, gateway-pool, sender-pool, session and campaign scope. Policies cover minimum and maximum wait, uniform jitter, bounded in-flight work, per-minute, hourly and daily allowances, active-campaign limits, burst size, cooldown, recovery ramp, failure/disconnect thresholds, automatic quarantine and message-type overrides.

Policies use draft, submission, independent approval, activation, rejection and retirement states. Resolution applies least-specific to most-specific precedence and returns the exact source policy IDs used by dispatch.

The dispatch throttle now consumes resolved pacing policy, applies message-type overrides, preserves the administrator's minimum wait, supports bounded deterministic jitter and permits adaptive health signals only to slow the route further.

## Multi-pool campaign routing

A campaign routing plan can contain multiple approved OpenWA sender pools, including separate `WHATSAPP_WEB_JS` and `BAILEYS` pools. Each route freezes gateway compatibility, allocation weight, maximum recipient allocation, reserved throughput, hourly and daily units and explicit cross-pool reallocation permission. Fallback remains fail-closed.

Deterministic shard-to-pool assignment prevents worker restarts from selecting arbitrary routes. Aggregate admission evaluates all reserved pools after safety margin and returns `ADMIT`, `HOLD` or `REJECT` with deadline and daily-capacity evidence.

## Database

Migration `0052_sender_pacing_and_multi_pool_routing.sql` adds pacing policy governance, campaign routing plans, per-pool route allocations, time-bounded capacity reservations and dispatch-shard route bindings.

## Validation boundary

The domain, policy-resolution, weighted routing, pacing and multi-pool admission paths are unit tested. Live PostgreSQL execution, Hostinger multi-node deployment and genuine OpenWA capacity calibration remain release gates.
