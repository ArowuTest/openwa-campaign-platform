# Release 0.8.20 — Controlled test sends and governed pool reallocation

This release closes two operational backend gaps from the OpenWA design discussion.

## Controlled test-message operations

Only maker-checker approved test MSISDNs may receive test sends. Test recipients are encrypted, lookup-HMAC protected and masked in operator responses. A test send freezes the campaign, message version and content hash, explicit OpenWA engine, gateway pool, concrete session, variables and idempotency key. The campaign worker renders the exact draft or approved version, applies governed session pacing, uses the signed gateway command path and records ACCEPTED, FAILED or UNKNOWN without consuming the campaign's production entitlement.

## Safe cross-pool movement

Campaign shards now retain their routing plan and assigned sender pool. A pending shard may be moved only when no recipient has reached submission or a terminal state, the shard has no active worker lease, the source route permits movement out and the target route permits movement in. Every movement records immutable actor, reason, evidence reference, source/target pools and fencing-version change.

## Pool-level reporting

Routing-plan reports now expose planned capacity and canonical recipient outcomes by sender pool, gateway pool and OpenWA engine. This preserves exact operational evidence for campaigns distributed across multiple `whatsapp-web.js` and Baileys pools.
