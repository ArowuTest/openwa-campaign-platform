# Checkpoint 0.3.1 — Integrity and Worker Runtime

## Purpose

This checkpoint remediates the principal defects identified in the 0.2.0 diligent audit. It is a development checkpoint, not a complete SRS release or production approval.

## Verified commands

The following commands pass in the isolated build workspace:

```text
go test ./...
go test -race ./...
go vet ./...
go build ./...
node scripts/check-typescript-syntax.js
python3 scripts/generate-traceability.py
```

## Material implementation completed

- Server-derived actor identity and MFA/session foundations.
- Maker-checker campaign and consent controls.
- Optimistic concurrency for mutable aggregates.
- Exact-payload idempotency for audit, messages, imports, jobs, outbox and gateway commands.
- Immutable message versions and audience snapshots.
- Transactional campaign-recipient entitlement and outbox creation.
- Fenced leases for imports, outbox, jobs and metrics reconciliation.
- Monotonic delivery evidence and provider-event replay protection.
- Signed gateway callbacks with timestamp and body binding.
- Final live consent/suppression checks before dispatch.
- Deterministic sender assignment subject to lease, heartbeat, health and in-flight bounds.
- Secure streamed import quarantine, file-signature validation and ClamAV scanner interface.
- Resumable protected import staging and merge foundations.
- Executable audience, campaign and metrics workers with bounded concurrency, health checks and graceful shutdown.
- Query-path-specific PostgreSQL indexes and schema tests for high-volume paths.
- Independent metric reconciliation that records drift without overwriting live counters.

## Metrics-worker issue resolved

The worker previously allowed parent cancellation to win a select race against a completed calculator failure. That could lose the durable failure record. The worker now drains a completed substantive outcome during shutdown and persists it, while ignoring ordinary context-cancellation errors caused solely by shutdown.

## Known blockers

- PostgreSQL driver dependency cannot be downloaded from this workspace. Binaries fail closed until a pinned `database/sql` driver is linked.
- No live PostgreSQL integration or migration run has been possible here.
- Docker on the user's desktop is not accessible from this workspace.
- OpenWA source and real WhatsApp transport are not yet imported.
- The NestJS gateway still uses the mock provider.
- Node lockfiles, full typechecking and production builds remain pending.
- Media dispatch remains disabled until authenticated short-lived object access is implemented.
- The complete 398-requirement SRS is not yet implemented.
