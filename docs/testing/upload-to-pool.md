# Test a reviewed upload across two sender pools

Use a test organisation, an approved manual review for its WhatsApp purpose, and two test pools. Use isolated storage and a simulated gateway for dispatch. The CSV in [fixtures/upload-cohorts.csv](fixtures/upload-cohorts.csv) contains 32 distinct synthetic international numbers, one repeated row and one invalid entry. Do not send this fixture to a real provider.

1. Open **Audience imports**, select the organisation, approved review and purpose, and upload the CSV with the MSISDN column mapped. For a pre-labelled external audience, upload each cohort as its own named file. The portal does not infer group labels from arbitrary columns.
2. Review the server preview: look for the duplicate and invalid row. Have a different authorised operator approve the import. Resolve any conflicts until the reconciliation balances.
3. On the completed import, select **Prepare sending cohorts → Number of groups: 2 → Prepare groups**. Record the two segment names. A count of 1 keeps an entire file together. Reopening the same upload and preparing the same count should reuse the segments. Do not rename, edit or mix group definitions for a send. Group sizes may differ.
4. Under **Campaigns**, create two drafts for the same organisation, review and purpose. Set adequate recipient limits, choose pool A for the first and pool B for the second, and select each compatible gateway. In each workspace submit the linked consent review, have an authorised approver confirm it, then **Start audience build**.
5. In **Audience builder**, select the same organisation and purpose. Open the first saved group, validate it and run its estimate. Select the corresponding audience-building campaign and schedule its snapshot. Repeat with the other group. Check the estimates and snapshots before releasing either campaign; for an otherwise empty test organisation with unchanged governance and no exclusions, the two counts together should be 32. Never infer the eligible count from uploaded rows.
6. Review each completed snapshot and follow the link back to its campaign. Select its snapshot ID and **Validate selected audience**. Submit and approve the intended message, run the approved controlled test, obtain the capacity hold and commercial and final approvals. If a prerequisite is absent, record the blocker; do not bypass it.
7. With a simulated gateway, **Release recipients**, then **Start dispatch** for each campaign. Check the pool ID and **Sending progress** counters. In dispatch the panel refreshes every 15 seconds; use **Refresh delivery counts** to check on demand. Exercise a delivery failure or unknown outcome in the simulator and reconcile it. An unavailable counter is different from a measured zero.

Disjoint membership is guaranteed for the same upload, split size and unchanged definitions. Separate uploaded files may contain the same number. Current consent, suppression and frequency caps still apply when estimating, freezing and releasing. The SQL integration test checks partition coverage, stability, exclusion of unrelated records, suppression, revoked consent and a rolled-back upload. A smoke test through a real gateway requires separate approved test recipients and available test sessions.
