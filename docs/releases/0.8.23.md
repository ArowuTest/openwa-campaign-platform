# Release 0.8.23 — Provider Capability Governance and Campaign Pre-flight

This release completes the first runtime integration of the governed provider capability registry.

## Included

- Provider-neutral, effective-dated capability definitions for OpenWA `WHATSAPP_WEB_JS` and `BAILEYS` routes.
- Maker-checker lifecycle: draft, submit, approve/reject, active and retire.
- Append-only lifecycle events in memory and PostgreSQL persistence.
- Administrative APIs for create, list, submit, decide, retire, resolve and event history.
- Recent MFA step-up for approval and retirement.
- Campaign creation and final execution boundaries now require an active compatible provider definition.
- Required message/event capabilities and the frozen adapter version are validated against the active definition.
- PostgreSQL readiness now checks for the capability-registry schema.
- Development runtime bootstraps explicit OpenWA capability definitions for both retained engines.

## Release boundary

This is code-level governance and pre-flight evidence. Live `whatsapp-web.js` and Baileys pairing, transmission and callback validation remain external release gates.
