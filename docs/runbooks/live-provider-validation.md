# Live provider validation runbook

This prepares the controlled live-provider exercise. No real WhatsApp session, Meta submission or provider event is claimed by this document.

## OpenWA engines
- Validate Baileys and WWebJS/Chromium independently on approved Hostinger nodes.
- Pair controlled genuine sessions and prove single-owner authority fencing.
- Exercise text, image, video and document where the governed capability permits it.
- Capture accepted, sent, delivered, read, failed, inbound and UNKNOWN evidence without automatic ambiguous resend.

## Direct Meta Cloud API
- Validate the exact WABA, phone-number, sender and credential authority on Railway.
- Prove TEMPLATE binding and authenticated FREE_FORM conversation-window eligibility.
- Exercise Graph submission plus signed delivery, inbound and STOP webhook reconciliation.
- Demonstrate credential rotation without routing Meta through OpenWA.

## Cross-provider failure safety
1. Inject controlled transport/provider failures before and after submission boundaries.
2. Confirm UNKNOWN remains sticky after ambiguous outcomes.
3. Confirm failover never creates a cross-provider duplicate send.
4. Reconcile provider message IDs, route authority, sender/session evidence and campaign recipient state.

## Evidence capture
Record environment, responsible operator, source/config fingerprint, immutable image digest, sender/session identifiers, timestamps and external evidence reference. Exercise status remains `PENDING_EXTERNAL` until all required live scenarios are executed and accepted.
