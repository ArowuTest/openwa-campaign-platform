# Release 0.8.25 — Transport Trust Boundaries, Trusted Evidence and Governed Session Lifecycle

## Baseline

- Branch: `work/backend-trust-boundary-hardening`
- Parent checkpoint: `0.8.24`
- Parent commit: `156cb61cfd39d932b6873ce1d938375cd2c7d860`

## Gateway and dispatch authority

- Every dispatch command now carries the current gateway node identity/version, sender-session lease and configuration versions, gateway-pool version, provider/engine/adapter identity, route reference and an expiring authority window.
- The control plane persists the current session authority before provider submission.
- The gateway validates the target node and runtime identity and rejects stale, mismatched or expired session authority.
- Idempotent replay remains bound to the immutable payload and route while volatile authority evidence is revalidated independently.
- Controlled test sends use the same governed authority and route-drift protections.

## Canonical sender lifecycle

- Sender sessions no longer enter `READY` when registered.
- The canonical lifecycle now includes `NEW`, `PAIRING`, `CONNECTING`, `READY`, `BUSY`, `DRAINING`, `PAUSED`, `DISCONNECTED`, `RECOVERING`, `FAILED_RECOVERY`, `RESTRICTED`, `QUARANTINED` and `RETIRED`.
- Invalid transitions are rejected before gateway side effects.
- Control-plane operations cover create, QR pairing, pairing code, start, health, drain, resume, stop, logout and delete.
- Pairing material is restricted to technical administration and recent MFA step-up.
- Logout and retirement are blocked while the session owns active campaign work.

## Real inbound event path

- The OpenWA wrapper subscribes to inbound-message events and stores them in a durable local outbox before forwarding.
- Inbound events can be correlated by recipient reference, quoted provider message ID or protected sender identity and owning session.
- The Go control plane validates the event contract and processes configured opt-out commands idempotently.
- Inbound content remains governed by the existing encrypted/minimised reply store and retention policy.

## Trusted assets and media

- Added trusted intake for message media, consent evidence and campaign evidence.
- File size, SHA-256 checksum and detected media type are derived from the stored bytes rather than trusted from a caller.
- Malware scan outcomes are recorded through a governed lifecycle; infected, indeterminate, failed or revoked assets cannot be approved or dispatched.
- Stored bytes are rechecked against the approved checksum and size before use.
- Non-text campaign messages require a frozen trusted asset and are checked against the exact provider capability definition and maximum attachment size.
- Asset revocation requires optimistic versioning, elevated permission, recent MFA and a meaningful reason.

## Consent-review governance

- Consent reviews are now created as drafts at organisation, source or exact campaign scope.
- Submission requires complete provenance, exact wording, privacy-notice evidence, purpose/controller evidence, permitted geography and either clean trusted evidence or a checksummed external evidence reference.
- Independent approval supports approved-with-restrictions, expiry and next-review dates.
- Approved reviews may be revoked or superseded by a governed draft revision with immutable lineage.
- Sample-review notes are bounded and reject common telephone-number and email-address patterns to minimise unnecessary sample PII.
- Campaign validation enforces the exact campaign scope where applicable.
